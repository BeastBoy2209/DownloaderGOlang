## ✨ Overview

`DownloaderGOlang` is a pet/academic backend project that accepts a batch of URLs, downloads them **concurrently in the background**, and lets clients poll for status and stream the resulting files back out — all without blocking the initial request.

Recently, the service was migrated from using native Go standard library concurrency (`errgroup`) to **Temporal**, providing highly reliable, distributed background job processing with built-in retries, timeouts, and tracking.

## 🧩 How it works

1. **Submit a job** — `POST /downloads` with a list of URLs and a timeout. The server immediately creates a job record in the database, schedules a Temporal Workflow, and returns the job's `id` with status `PROCESS`.
2. **Download in the background** — a Temporal Workflow orchestrates the downloading of files in parallel by scheduling separate `DownloadFileActivity` tasks. This provides built-in retries for network failures and isolates the execution of each download.
3. **Partial failure is fine** — if one URL fails completely, the rest keep downloading. The workflow marks the job as `DONE` once every file has either succeeded or failed.
4. **Retrieve results** — `GET /downloads/{id}` reports the status of every file (its `file_id` on success, an error code on failure). `GET /downloads/{id}/files/{file_id}` streams the raw bytes back.

## 🔌 API

All responses include a `Request-Id` UUID header. If the client provides a `Request-Id` in the request, it will be preserved; otherwise, a new one is generated by the middleware.

### `POST /downloads`
Create a download job. Returns immediately.

```json
// Request
{
  "files": [
    { "url": "https://google.com" },
    { "url": "https://somehost.com/test.pdf" }
  ],
  "timeout": "60s"
}

// Response
{
  "id": 12,
  "status": "PROCESS"
}
```

### `GET /downloads/{id}`
Check job status.

```json
// Happy path
{
  "id": 12,
  "status": "DONE",
  "files": [
    { "url": "https://google.com", "file_id": 79 },
    { "url": "https://bing.com",  "file_id": 80 }
  ]
}

// Partial failure
{
  "id": 12,
  "status": "DONE",
  "files": [
    { "url": "https://google.com", "error": { "code": "TIMEOUT" } },
    { "url": "https://bing.com", "file_id": 80 }
  ]
}
```

### `GET /downloads/{id}/files/{file_id}`
Streams the downloaded file's raw bytes (`Content-Type: application/octet-stream`).

## 🏗 Architecture & design principles

The service is built around a few deliberate engineering constraints:

| Principle | How it's applied |
|---|---|
| **Clean architecture** | Responsibilities are split across `transport`, `temporal`, `usecase`, `domain`, and `repository`. Dependencies point inward. |
| **Interfaces everywhere** | File storage is an abstract `Repository` interface (implemented on top of PostgreSQL using `sqlx`), enabling dependency inversion and easy mocking in tests. |
| **Robust Background Jobs** | Migration to **Temporal** allows us to separate HTTP context timeouts from background job execution, bringing out-of-the-box reliability and activity retries. |
| **Structured Logging** | `log/slog` is used consistently across the codebase for structured, JSON-formatted logging, enforced by strict linters (`sloglint`). |
| **Graceful shutdown** | OS signals are caught and the Echo HTTP server and Temporal Worker are shut down gracefully. |
| **Middleware** | Custom Echo middleware is used for generating or persisting a `Request-Id` UUID on every HTTP request. |
| **Tested usecases** | Core services and Temporal workflows/activities are covered by mocked-dependency unit tests using `testsuite.WorkflowTestSuite`. |

## 🛠 Tech stack

- **Language:** Go `1.26`
- **HTTP:** [`labstack/echo`](https://github.com/labstack/echo) v5
- **Database:** PostgreSQL via [`jackc/pgx`](https://github.com/jackc/pgx) + [`jmoiron/sqlx`](https://github.com/jmoiron/sqlx)
- **Background Jobs:** [`go.temporal.io/sdk`](https://github.com/temporalio/sdk-go)
- **Configuration:** [`caarlos0/env`](https://github.com/caarlos0/env) + [`joho/godotenv`](https://github.com/joho/godotenv)
- **Logging:** Standard library `log/slog`
- **Testing:** [`stretchr/testify`](https://github.com/stretchr/testify) + [`uber-go/mock`](https://github.com/uber-go/mock)

## 🚀 Getting started

### Prerequisites
- Go 1.26+
- A running PostgreSQL instance
- A running Temporal Server (e.g., via `temporal server start-dev`)

### Setup

```bash
# 1. Clone the repository
git clone https://github.com/BeastBoy2209/DownloaderGOlang.git
cd DownloaderGOlang

# 2. Configure environment variables
cp .env.example .env   
# Fill in your DB credentials, server settings, and Temporal configs:
# TEMPORAL_TASK_QUEUE=DOWNLOAD_TASK_QUEUE
# TEMPORAL_ACTIVITY_TIMEOUT=10m

# 3. Apply database migrations
# (run the SQL files in db/migrations against your PostgreSQL instance)

# 4. Start the Temporal Server locally in a separate terminal
temporal server start-dev

# 5. Run the service
go run ./cmd/app
```

### Running tests

```bash
go test ./...
```

## 📚 About this project

This repository was built as a **final/capstone assignment** for a Go backend course, aimed at demonstrating a solid understanding of:

- Designing an async job-processing HTTP service from a written contract/spec
- Structuring a Go service with clean, testable layers
- Migrating complex concurrency logic to reliable workflow engines (Temporal)
- Writing meaningful, mocked unit tests for HTTP services and distributed workflows

It is **not** intended for production use — it's a learning artifact, shared for portfolio and educational purposes.
